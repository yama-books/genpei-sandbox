## コアのイベントとの照合

| 観測 | コア側で確認できるもの | 同じ意味にしてはいけないもの |
| --- | --- | --- |
| `destination_selected` | `chooseTarget`は目的地を変更した場合だけ`decision`を記録 | 初期配置は判断ログではない。助言による変更は`intervention`。同じ刻で選択・到着してtargetがnullに戻ると、観測では選択が見えない |
| `reconsidered` | `lastDecision/lastScores`の変化 | 判断実行回数ではない。同じ結果を再選択しても差分がなく、表示用スコアの変化だけの場合もある。運命側の`fate.decisions[].kind="reconsidered"`とは別物 |
| `movement_started/advanced` | x/y差分 | 毎刻の移動ログはない。コアの`movement`ログは一部地点への到着であり、進行ログではない |
| `arrival_observed` | arrivals増加。到着先次第で`facility`・`warning`・`fate`・`movement`ログ | 現代施設の利用成功・道路到着・GPS確定ではない。支払失敗でも到着カウンタは増加する |
| `destination_cleared` | 到着数が増えずtargetが消える。POI解除は`system`ログ | 到着と混同しない。個別の人物到着ログは生成されない |

新規8テストのうち、同刻の選択・到着、進行ログ不在、施設利用失敗後の到着、ログ消失後の複数到着を、実際の`stepWorld`等の呼出しで再現する。イベント本文の日本語を解析して構造化イベントを推定しない。

`world.events`は新しい順で最大140件。同刻に複数イベントがあり、安定したイベントID・通し番号・完全履歴保証がない。間引き観測では複数到着も`arrival_observed`1件になる。二つのsnapshotと残存ログから完全な行程順序・正確な発生刻を復元しない。`completeEventHistory:false`を保持する。

## 実地移動を接続する前の不足契約

| 論点 | 現状と不足 | 将来の受入条件（未実装） |
| --- | --- | --- |
| 人物位置の根拠 | x/yは`abstract`・stage_units、`realGeo:null`。POI終点と最後に訪れた施設は人物の実位置の証明ではない | 人物に紐付く位置の取得元、基準座標系、精度、観測時点、検証状態と失効条件を定義。創作配置なら創作であることを保持 |
| 施設の信頼性・鮮度 | 名称・座標・出典の形式検査。`unreviewed_reference`。取得日が解釈可能でも古い・未来の日付を受け付ける。存在、営業、通行や典拠真正性は未保証 | 利用目的別の情報源・許諾・検証担当・更新期限、期限切れ/不一致時の棄却条件を独立審査。任意の期限値をここで決めない |
| 年代 | 施設・道路は`present_day`。物語の1185はグレゴリオ暦のsimulation clockではない | 現代参照と1185の証拠を分離。旧国名エンジンの正式ID、年代付き幾何、典拠・権利を受領して照合。sourceId付き形式回答だけで歴史地理を確定しない |
| 行程への紐付け | 施設間previewは呼出側が出発施設を選ぶ。人物の位置・最後の施設と違ってもreadyになり得る | timeline/agent/journey/requestの識別と出発・目的地の版、開始時の位置根拠、途中変更・取消・遅延応答の採否を定義 |
| 時間と距離 | コアは1刻あたり架空距離5/15、到着時は残距離。previewのmetersと変換契約なし。距離400/40000mでも同じコア軌跡 | 刻の意味、移動手段、速度・休息・補給・到着判定、経路上進捗と保存復帰を別途設計。現在の距離検査は線形状の実長検証や所要時間保証でもない |
| 障害・再試行 | pending/failed/stale/unavailableと移動を分離。失敗はpreviewなし、`canMoveAgent:false`、`simulationEffect:"none"`、自動retryなし | 現行は架空移動を継続。将来道路移動を入れる場合のみ、待機/取消/再経路・費用・乱数・保存復帰を明示設計。NoRouteを直線道路や瞬間移動へ置き換えない |
| 観測の系列 | previousは同一timelineで呼出側が管理。seed/agent/tickだけでは同seedの別分岐を識別不能 | MAP-05では新規世界・別保存・分岐切替・巻戻し時にpreviousを破棄。同じ保存時点のpreviousを一緒に復元する場合のみ継続。完全履歴が必要なら別のコアイベント契約を設計 |

歴史地理の形式回答が`ready_for_review`でも、`externalProvinceId:null`・geometry/route未解決は変わらない。現代の距離・道路線・施設到着から1185年の行軍時間、古道、海岸線を生成しない。

## MAP-05への利用指針

- 移動パネルは既存SIM-04 APIを読み取る。新スキーマや本書専用APIへの移行は不要。
- 観測差分の出来事とコアの残存ログを区別して表示。ログ不在を「出来事なし」と断定せず、スナップショット間の完全な内部履歴を主張しない。
- 同刻・同seedでも別系列は判定不能。previous破棄/復元を画面側ライフサイクルで管理。観測だけの初回はevents空を許容する。
- 到着と施設利用成功、観測の再判断と運命の再判断、施設間previewと人物行程を別の意味として説明。
- MAP-04の運命表示、公開版の外部経路無効、既存リクエスト整合検査を維持。人物マーカーを実地図へ追加しない。
