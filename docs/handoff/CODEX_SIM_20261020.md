## 計測と読み方

128シードは `(i+1) * 0x9e3779b1` の32bit値。小さな連番シードだけに寄せず、一覧をJSONに保存。
引力0/50/100 × POIなし/人工4件 × 介入なし/有限3回、240刻まで観測。
介入は0刻の義経への屋島助言、20刻の交渉助言、45刻の資金・食料支援。
介入は拒否され得る。引力設定が助言の受諾率を変える実装ではない。
これは複合介入方針の比較で、各介入を単独で評価したものではない。

各条件を独立して2回実行し、各刻の人物状態・RNG・運命状態・その刻の全イベントをSHA-256で比較。
140件のログ上限から脱落したイベントも比較対象。最終世界全体も比較。
さらに30刻のJSON保存を読み戻し、以後の介入を同じ時点で適用して連続実行と比較。
シードだけでなく、エンジン版、施設の並び、操作の時点と順序も再現条件。
ソースハッシュはBOMを除去しLFへ正規化するのでGit checkoutの改行設定に依存しない。

「到達」は240刻までの義経の初回訪問。「期限内」は82刻未満。「未到着の結末」は112刻までの章判定。
これらは異なる。引力0・POIなし・介入なしは章の全128件が未到着だが、その後を含めると125件が訪問。
施設利用は成功した到着回数で、滞在時間ではない。金欠の到着警告と残金9未満の人物刻を別に集計する。
移動停止は「目的地へ移動中に同一座標が60刻続く」観測指標。有限観測だけで永久停止の不存在を証明しない。

現在の初期資源では撤退系が0件となる偏りもそのまま記録する。
撤退・延期後の回復・遅参・訪問後の失機は状態別の単体テストで到達可能性を確認。
見栄えの良い分布にする目的の閾値変更は行っていない。
低引力でのPOI効果には、施設が屋島近傍の抽象座標へ集まる配置による影響が含まれる。
これらの分布はゲーム試作値であり、歴史的な確率ではない。

## 乱数と状態遷移

世界に保存されるxorshift32 `world.rng` を共有し、人物配列順に遷移する。
各刻: 世界刻加算 → 人物ごとに食料・体力の消費 → 必要なら目的地再選択 → 移動/到着 → 全員の後に章判定。
目的地再選択は初期/到着後/10刻周期（助言の有効期間外）。探索判定で1回乱数を消費。
支援は乱数を消費せず、屋島助言と交渉助言は受諾判定で各1回消費。
章の交渉/未到着/撤退は戦闘乱数を消費せず、交戦判定で1回消費する。
支払可能性の絞込みでは乱数を増やしていない。ただし候補が変わると以後の軌跡と判定時機が変わり、版をまたぐリプレイ一致は保証しない。

## UI・地図担当への意味契約案（未実装）

提案名: `movementObservationV1(world, agentId)`。これは将来の読取専用アダプター案で、現在のexportではない。
既存呼出は `snapshot(world)` の人物情報を引き続き利用できる。
変更理由: 模式図上の移動と現代POIの緯度経度を混同しないため。
想定例:

```json
{
  "schemaVersion": "movement-observation/1",
  "tick": 50,
  "agentId": "C036",
  "destinationId": "modern-1",
  "positionDomain": "abstract",
  "position": {"x": 700, "y": 300, "unit": "stage_units"},
  "movementStatus": "moving",
  "currentStationId": null,
  "route": null,
  "agentGeoPosition": null,
  "destinationModernLocation": {"lat": 34.3573, "lng": 134.1012},
  "provenance": {
    "position": "fictional_simulation",
    "movement": "abstract_straight_line_only",
    "destination": {"source": "synthetic_sim_fixture", "licenses": ["CC0-1.0"]}
  }
}
```

- `agentId`: 既存人物ID。部隊や同行者の位置を人物から自動生成しない。
- `destinationId`: `agent.target`。到着直後はtargetがnullになり、`currentStationId`が到着先を保持する。POI IDは導入順の一時IDなので、異なる取得結果間の永続キーには使わない。
- `positionDomain`: 現状は常に `abstract`。将来の `real_geo` は検証済み位置・経路・出典が揃ったときだけ使う。現代POIの座標を人物の現在地へコピーしない。
- `movementStatus`: `moving`（targetあり）、`arrived`（targetなし・currentStationIdあり）、`awaiting_decision`（どちらもなし）。`blocked` は将来の経路失敗用で、現在の低体力を停止と扱わない（体力が低くても毎刻5仮想単位移動）。
- `provenance`: 人物位置と目的地資料を別々に保持。現代座標は目的地の属性であり、史実の合戦地点ではない。実POIではsource/licenses/attributionsを欠かさない。
- 施設解除時は既存の `removeModernPois(world)` がtarget/currentStationId/recentlyVisitedを解除する。アダプターが独自にtargetを書き換えない。

呼出例（将来）: `movementObservationV1(snapshot(world), "C036")`。
必要テスト: 到着直後のtarget null、POI解除、保存復帰、出典保持、GPS未取得時のagentGeoPosition null、real_geoへの無根拠な昇格防止。
影響範囲: 新規アダプターとUI読取部分のみ。地図モジュール・既存core APIの実装変更は所有者との調整後に別PRで行う。
