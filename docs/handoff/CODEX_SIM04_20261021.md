## 空間・用途の契約

| 対象 | positionDomain | 用途 | 現時点の値・制約 |
| --- | --- | --- | --- |
| 人物 | `abstract` | `simulation` | 既存x/y、単位stage_units。`realGeo:null` |
| 目的地施設の参照 | `modern_wgs84` | `facility_reference_only` | 施設の現代座標・出典。人物位置への代入不可 |
| 施設間の経路 | `modern_wgs84` | `facility_to_facility_preview` | 既存MAP-03の審査を通った現代道路のプレビューのみ |
| 歴史地理 | `historical_geo` | `historical_context_only` | 既存1185年照会、`unresolved`、geometry/routeともnull |

`spatial.destination.validation` は `unreviewed_reference`。既存の施設属性を複製した参照であり、施設の存在・営業・座標や出典の真正性を新たに保証しない。経路には既存MAP-03の検査が別途必要。
架空座標と現代座標の逆変換、現代施設への到着を人物GPSとする推定、中世の道路・境界・海岸線・所要時間の生成はしない。
歴史側は旧国名エンジンの正式な地物ID、年代付き幾何、典拠、利用許諾と別途承認を待つ。現行の歴史レスポンス検査を通っても人物移動は解禁されない。

## 提案API 1：現在状態と観測された遷移

```js
import { getAgentMovementState } from "../../prototype/movement-state.mjs";
let previous = null;
// 毎tickまたは介入・POI変更の後、同じworld系列・同じagentで呼ぶ。
const state = getAgentMovementState(world, "C036", { previous });
previous = state;
```

`schemaVersion:"agent-movement/1"`。未知のagentはnull。返却値はJSON保存可能で、worldを参照共有しない。

- `movementStatus` / `placement`：既存読取APIの `idle/moving/arrived/blocked` をそのまま使用。
- `decision.reason/candidates`：現在の `lastDecision/lastScores` の複製。候補の得点はゲームの関心・評価で、歴史的確率ではない。JSON保存と同じく得点の-0は0へ正規化。
- `decision.nextEvaluation`：targetなしなら `next_tick`、ありなら `periodic_or_intervention`。予約や実行済みイベントではない。
- `transition.basis`：同じバージョン・agent・seed、未来でないtick、必要フィールドを持つpreviousなら `snapshot_difference`。それ以外は `unavailable`、eventsは空。
- `capabilities`：実地図への人物配置、現代道路への追従は常にfalse。

| transition.events | 検出根拠・意味 |
| --- | --- |
| `destination_selected` | 前回と異なる非nullの目的地を観察。初回配置は選択イベントと推定しない |
| `reconsidered` | 判断理由または候補評価の変化を観察。内部で同じ結果を再選択した事実までは保証しない |
| `movement_started` | 座標変化があり、前回はmovingでない、または目的地が変化。新しい行程の移動を観察 |
| `movement_advanced` | その他の座標変化。実距離・速度・GPS・道路上の進捗を意味しない |
| `arrival_observed` | arrivalsカウンタの増加。複数到着があってもこのイベントは1件 |
| `destination_cleared` | 目的地が消え、到着カウンタは増えていない。POI解除等を含み、到着と混同しない |

blockedの観測では遷移イベントを出さず、不明な目的地・不正座標の既存理由を保持する。
到着は状態、到着後の次tickの選び直しはdecisionの予定として分離する。
エンジンは同じtick内で選択・移動・到着まで行えるため、独立した `selecting/starting/reconsidering` 状態を捏造しない。
`completeEventHistory:false` は常に保持。間引いた観察から中間の順序・正確な発生tick・全イベントは復元できない。

previousは呼出側の観測用データ。worldへ保存する必要はなく、同じ保存時点のpreviousを一緒にJSON保存して復帰できる。
別worldへの切替、同じseedでの再開始、ロード先変更、時間巻戻しではpreviousを破棄すること。
seed/agent/tickの検査は誤接続を減らすためのもので、同seedの分岐系列の同一性の証明ではない。
完全な内部イベント列が必要になった場合は、別PRでcoreのイベント契約を設計する。

## 提案API 2：経路取得状態を安全に参照

```js
import { getAgentRouteState } from "../../prototype/movement-state.mjs";
// requestは既存makeModernRouteRequestの出力。出発施設は呼出側が明示選択。
// abstract人物座標や過去のcurrentStationIdから出発実座標を推定しない。
const pending = getAgentRouteState(world, "C036", { request, status: "pending" });
const result = await client.fetchRoute(request); // 既存MAP-03B client、呼出側が明示実行
const settled = getAgentRouteState(world, "C036", {
  request, status: "settled", result,
});
```

新モジュールはネットワークもタイマーも起動しない。`result` は同じrequestに対する既存clientの返却値を渡す。
requestを保持せず別照会の結果を混ぜないこと。同じ施設対への再照会は呼出側が要求IDで管理し、UIでは最新の要求だけ採用すること。
このAPIは人物の現在の目的地に紐付く**施設間プレビューの関連付け**であり、人物の行程・出発施設・居場所の確定ではない。

| status | 意味 |
| --- | --- |
| `not_requested` | attemptなし |
| `pending` | 現在の施設属性とrequestが一致し、取得中 |
| `ready` | MAP-03の形式・経路形状・典拠検査が再度成功 |
| `failed` | 通信、NoRoute、timeout、レート制限、応答不正等 |
| `stale` | 目的地・名称・座標・典拠等がrequestから変わった |
| `unavailable` | 人物の状態不正、出発/目的施設なし、典拠不足、同一施設等 |

毎回worldの現代施設一覧から既存makeModernRouteRequestで再構成して照合する。`modern-1`等の解除・再採用によるID再利用だけでは古いrequestを採用しない。
同じ属性の施設対の経路はtickを越えて再利用可能。人物の経路進捗や行程IDとしては使えない。
`result.ok` や `canDrawPreview` フラグだけを信用せず、既存reviewModernRouteへ形状と典拠を渡して再検査する。これは出典の認証や通行可能性の証明ではない。

失敗時はroutePreview:null、canDrawPreview:false。成功時でもcanMoveAgent:false。
`simulationEffect:"none"`、自動リトライなし。抽象直線の移動は既存規則のまま継続し、取得失敗を新たな人物の再判断・瞬間移動・停止の原因にしない。
再試行・取消・プロバイダー切替は呼出側の操作と既存クライアントの制約に従う。公開サイトの外部経路無効設定を変更しない。
到着してtargetがnullになった後の関連付けはunavailable。施設間プレビュー自体の表示継続は既存MAP-03のUI側で判断する。
