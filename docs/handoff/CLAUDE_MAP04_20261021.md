## 2. 実装済み・検証済みの内容

### 実装

`prototype/map/fate-timeline.mjs`（新規。読み取り専用で、判定は行わない）：

- `buildFateStages(fate, tick)`：「機会 → 決断 → 再判断 → 結末」の4段階を返す。材料は `fate.decisions` と `resolution` だけ。
  - 延期したときの理由（causes）は、記録をそのまま写す。
  - 再判断の段階は、次のいずれかになる：第N刻に再判断（進行中）／回復・帰還待ち（`reconsidered`）／猶予後に判断（延期の後に確定）／延期なし。
- `endingLabel(resolution)`：`withdrawal` は次のように分ける。
  - 第112刻の締切で確定 →「時機を逸して断念」
  - 屋島の外で確定（`metrics.atDecisionSite===false`）→「屋島の外で攻勢断念」
  - それ以外 →「攻勢断念」
  - `retreat` は「屋島で撤退」と表示する。
- `readinessView(leader, metrics)`：体力・食料は、判定と同じく丸める前の実値で基準（15・12）と比べる。表示は `floorTenth` で小数第1位に切り捨てる（14.96 → 14.9）。行動余力は、判定と同じく丸め済みの `metrics.readiness` を46と比べる。
- `upcomingCheckpoints(fate, tick)`：次の区切りを返す。機会の接近（35）、猶予の終了（`postponedUntil`）、相手勢力の退避（82）、締切（112）。
- `createTrail` / `recordTrail` / `truncateTrail`：画面側だけの観察記録。義経の刻ごとの体力・食料・在場と、施設利用・介入・警告・運命の出来事を持つ。保存地点に戻すと、その刻より後を消す。
- `chartModel(trail, fate, tick, dims)`：グラフの座標を計算する。第0〜112刻、最低ライン、猶予帯、屋島に滞在した区間、出来事、判断、現在の刻。狭い画面用の座標 `CHART_COMPACT` もある。
- `OBSERVATION_SCENARIOS` / `applyObservationScenario`：観察条件の「通常」と「資源不足」。資源不足は義経の体力40・食料20・所持金0（SIM-03の複合不足と同じ値）。変えるのは初期値だけで、乱数は消費しない。

画面（`app.mjs` / `index.html` / `style.css`）：

- 「運命の刻」パネルに次を並べた：4段階の表示、直近の判定理由、現在値（現在地・体力・食料・行動余力・次の区切り）、経過グラフと凡例、折りたたみ式の道中記録、観察条件の選択（選び直すとリセット）。
- これまでの進行バー（`#fate-progress`）は、グラフで置き換えたため削除した。`#fate-phase`、`#fate-description`、`#fate-reasons`（結末の理由と道中の出来事）は残してあり、既存テストと `tests/browser-smoke.html` の参照先も変わらない。
- 観察記録は、1刻進めたとき・結末まで早送りしたとき・描画のたびに更新する。リセットで初期化し、保存地点に戻すと巻き戻す。
- グラフは画面幅が変わると描き直す。

- テスト用HTTPサーバーは自分で起動し、PIDを記録してそのPIDだけを止めた。
- `reconsidered`（回復・帰還待ち）は、通常の自律プレイではほぼ起きない。そのため、SIM-03のテストと同じく状態を直接作って単体テストで確かめた。ブラウザでの確認は、延期 → 屋島の外で断念の経過だけ。
