- プロジェクト: **genpei-sandbox**（仮題「源平異聞録」）
- 文書版: **0.1 / 構想段階**
- 記録日: 2026-10-17
- 正本候補: \`yama-books/genpei-sandbox\`
- 実装状況: **未実装**。本書の数値・人数・イベント件数・画面は設計案であり、実測結果ではない。
- 決定済み: **自動観察とプレイヤー介入を両立**する。
- その他の技術・ゲームバランス・データ境界は今後の検証対象。

## 1. 目的とコンセプト

歴史上の人物が、現在の日本列島に存在する鉄道・商店・飲食店・温泉・遊興施設・動物園・山林・港などを利用して自律的に活動したら、治承・寿永の内乱や『平家物語』の展開はどう変わるかを観察・実験する、歴史地理×人物エージェント×箱庭シミュレーター。

**史実には重い「引力」があり、結末には自由がある。**

ゲームの主たる体験は、人物が目的と嗜好に応じて移動・休息・交渉・補給・合流・敵対・寄り道をする様子を地図上で見守ること。任意の時点で助言・支援・直接介入・運命の分岐を試し、介入の有無による違いを比べられる。

歴史上の悲劇は娯楽的な得点イベントに単純化しない。史実／軍記上の描写／伝承／ゲームの仮説は明示的に区別し、学習用の典拠表示を提供する。

### 対象範囲

- 当初の歴史的主軸は治承・寿永の内乱（1180–1185年）。
- 背景史には伊勢平氏の形成、保元・平治の乱（1156・1159年）、1189年までの義経・奥州藤原氏関係も含む。
- 将来の拡張は壇ノ浦、一ノ谷、宇治川、木曽義仲、伊勢平氏、平家落人伝承、義経北行伝説等。
- 『平家物語』の異本・後代の芸能・地域伝承は、史実と混同せず個別の資料レイヤーとして持つ。
- ゲーム内の日付はシミュレーション固有の時間軸。実際の1185年の出来事の日付や人物の生存期間と別管理する。

## 2. 体験と操作モード

1. **観察**：複数の人物・部隊が自律行動。追跡、視点切替、速度変更、停止、時間軸閲覧。
2. **助言介入**：進路や活動について提案するが、人物は性格・目的に応じて受諾・拒否できる。
3. **資源介入**：食料・資金・情報等を有限の予算から提供し、状況を変える。
4. **直接介入**：人物／部隊へ明示的な命令を出す。自律性への干渉として記録。
5. **運命介入**：重要イベントの結末を仮定したIF枝を作る。原典の出来事は書き換えない。
6. **比較実験**：同じ初期状態・施設データ版・乱数シードから複数の歴史を実行・比較する。

介入の強さはログに残し、観察のみの実験と混同しない。

## 3. 歴史の三層構造

| 層 | データ | 変更規則 |
| --- | --- | --- |
| 史料・基盤 | 実在確認、系譜、生没年、歴史上の関係、事件、証拠、異説 | **変更不可の参照データ**。訂正は監査・版更新でのみ行う |
| 歴史的引力 | 人物と運命の場所・人物・逸話の関係、発生条件、物語上の重要度 | 行動の強い動機。ただし行動自体を確定させない |
| 現代の偶然 | 現在の施設、交通、費用、疲労、交渉、娯楽、遭遇、偶発事象 | シミュレーションごとに変化 |

**注意**：史料的確実性とゲーム内の「引力の強さ」は無関係。典拠として弱い伝説も、伝説モードでは高い引力を持てる。

## 4. 中心データモデル

別々のID空間で管理する。

- \`Person\`: 安定ID、表記・異名、生没時期（範囲可）、証拠区分、出自・本拠、活動、出典。
- \`PersonClaim\`: 「人物Xは地域Yに滞在」などの個別主張、典拠位置、確認状態、異説。
- \`Relationship\`: 人物間の家族・主従・友敵関係、成立／解消時点、証拠。
- \`Faction\`: 時期依存の政治軍事勢力。姓や氏族と同一視しない。
- \`HistoricalPlace\`: 史跡／伝承地／推定地、点・線・面、精度・不確実性、関連事件・典拠。
- \`HistoricalEvent\`: 史実の出来事と軍記・伝承のエピソード。場所・人物・時期・典拠・異説。
- \`Facility\`: 現代のPOI、原名称・カテゴリ・座標・出典・ライセンス・取得日時・分類の確度。
- \`TransportEdge\`: 道路・鉄道・海路等の経路と所要時間・費用・通行可能条件。
- \`AgentState\`: シミュレーション中の人物の疲労、空腹、関心、金銭、意思、記憶、現在地等。
- \`UnitState\`: 武将個人とは別の部隊人数・資源・所在・指揮系統。
- \`SimEvent\`: 起こった／起こらなかった行為、原因、変更値、根拠、乱数キー、実行時刻。
- \`Intervention\`: 人間の介入種類、時点、対象、条件・効果。
- \`RunManifest\`: 世界データ版、史料データ版、規則エンジン版、設定、乱数シード。

個々の主張は \`claim_id\` に対して \`source_id\` を紐付け、人物カード全体に一つの曖昧な「出典」を付けるだけで済ませない。

## 5. 歴史的引力エンジン

人物と歴史地点の組ごとに \`fatePull\`（0〜100）を計算する。

概念モデル：

\`\`\`text
fatePull = clamp(
  因縁の基本値
  + 物語進行度
  + 記憶・類似物による刺激
  + 未訪問による蓄積
  - 危険・移動不能・競合する義務,
  0, 100)
\`\`\`

試験用の暫定段階：0–29 潜在、30–59 意識、60–84 強い衝動、85–100 運命的接近。境界や係数は検証によって変更する。

- **強い引力はワープでも自動到着でもない**。現実的な移動条件を満たす必要がある。
- 運命の場所への接近を人物の長期目標とし、史跡の地点または推定範囲に近づくとイベント候補を評価。
- 必須の逸話については「接近中 → 遭遇 → 成立／不成立／到達不能／別展開」の状態機械を使う。
- 死亡・拘束・地理的遮断・介入などで到達不可能なら、未到達の理由も歴史日誌に残す。
- 記録上重要な出来事と同じ**結末**の強制はしない。
- 厳密な発生条件を持つ歴史シナリオと、伝承・創作の分岐は切り替え可能にする。

例：那須与一と屋島の駒立岩・祈り岩は伝承地として関係付ける。現代の座標が12世紀の射手の正確な立ち位置を証明するものではない。

## 6. 自律行動

### 人物が保持する状態

| カテゴリ | 値の例 |
| --- | --- |
| 身体 | 体力、疲労、空腹、負傷 |
| 心理 | 士気、恐怖、好奇心、忠誠、未練 |
| 資源 | 現金、食料、装備、移動手段 |
| 能力 | 射術、統率、戦術、交渉、野営、交通利用 |
| 嗜好 | 娯楽、温泉、食事、自然、動物、鉄道 |
| 社会 | 主従、家族、友好、敵対、信頼、名声 |
| 歴史 | 宿命の目標、典拠に基づく人物像、逸話への関係 |
| 計画 | 当面の使命、予定、経路、現在行動、経験記憶 |

行動サイクル：

1. 生存・安全・移動可否などの硬い制約を評価。
2. 補給・移動・警戒・合流・交渉・娯楽・参拝・休養などから候補を生成。
3. 目的達成、史実の引力、生理的必要、趣味、社会的影響、時間費用を正規化し効用得点を付ける。
4. 上位候補を人格に応じた確率で選ぶ（常に最高得点を固定採用しない）。
5. 行動結果、費用、経路、学習、関係を更新してログ記録する。

**歴史的人格**と**現代の付加的人格**は分離する。現代転移モードでは出生地近くの現代施設を史実上の性格の説明には使わず、嗜好のIF補正にのみ用いる。現代転生モード（将来）では現代の居住環境から別の人格を形成する。

AI文章生成は決定ロジックの正本にしない。シミュレーション本体は決定的な計算系とし、自然言語の観察日誌は計算結果に基づく表示とする。

## 7. 現代施設と資源

現代POIはゲーム世界の実在施設に対応するが、「現実の店舗の在庫／資産／収容人数」を保証するものではない。

| 分類 | 仮想的な効果 | 制約 |
| --- | --- | --- |
| 飲食店・スーパー | 食料購入、疲労回復、兵站 | 費用、供給量の仮定、移動・調達時間 |
| 銀行・商業施設 | 資金調達機会、交渉 | 信用、審査、取引条件の抽象モデル。接近だけで現金増加なし |
| 宿泊・温泉 | 休養、士気回復、長居の誘惑 | 宿泊費、時間、営業の不確実性 |
| 娯楽施設・ゲームセンター | 娯楽、技能訓練、寄り道 | 分類確度、消費、時間 |
| 動物園・水族館 | 癒やし、好奇心、予定変更 | 入場条件、時間、費用 |
| 駅・港 | 距離移動、集結・離散 | 路線・運賃・運行は外部の経路データが必要 |
| 寺社・史跡 | 信仰、記憶、運命イベント | 史跡との同一視はしない |
| 森林・山地 | 野営、隠密、地形障害 | POIではなく土地利用／地形情報で評価 |

- 個人の所持金・食料と部隊の兵站を分離する。
- 武将が休息や遊興に出かけても部隊が自動追随しない。命令・随伴条件が必要。
- 調達は購入・協力・労働・交易などの仮想合法モデルを基本とする。
- 推定供給能力は「ゲーム仮定」と明記し、外部施設の実データと区別する。
- \`unknown\` POIを無理に娯楽施設と判定しない。

## 8. 地理・交通

- POIの位置情報（OpenPOI）と、道路／鉄道接続／航路／地形／歴史史跡は**別レイヤー**。
- 初期移動：徒歩、簡易鉄道ネットワーク、明示した固定航路。自動車と実時刻表は拡張機能。
- 海峡横断や山越えは直線距離だけで自動成立させない。
- 土地利用や高低差は、山林・市街地・水域等の移動コストと野営に反映する。
- ルート不明、航路廃止、データ欠損は推定扱いとし、無限移動ループを防止する。
- 史跡は「点で確定」「推定点」「線・範囲」「伝承地」などの空間精度を別途保持する。

## 9. 歴史イベント

イベントは \`historical_basis\`（典拠を伴う過去の叙述）と、\`simulation_trigger\`／\`outcomes\`（現在のシミュレーション規則）を分ける。

初期・屋島編の候補（史料確認前の企画名）：

1. 屋島奇襲
2. 佐藤継信の身代わり
3. 扇の的
4. 義経の弓流し
5. 平氏側の海上撤退
6. 屋島戦の終結

\`扇の的\` は、与一が対象地域に存在し、対峙・挑戦の条件が揃う場合に候補化。射術、疲労、心理、環境で \`success | failure | alternative | not_occurred\` に分岐。原典の結果を消さず、ゲームの結果と並べて解説する。

伝承編として、椎葉村の平家落人伝承、各地の安徳天皇生存伝説、義経北行伝説等を追加可能。ただし義経＝チンギス・ハン説などは歴史的根拠が確立していない伝説・創作のIFとしてのみ表示する。

## 10. 観察・介入UI

### PC

- 中央：地図。人物、軍勢、施設、鉄道・海路、史跡、歴史的引力をレイヤー表示。
- 右：選択人物の現在地、任務、体力・資源、行動理由、歴史的因縁。
- 下：時刻・進行速度（停止、×1、×10、×100）・分岐保存。
- 左／下部：重要度別の観察日誌と人物検索。
- 重大事件発生時：設定により自動減速／一時停止し、その場面に注目。

### スマートフォン

地図を主役とし、人物カード・観察日誌・介入は下から開くパネル方式。タップ領域・文字サイズ・キーボード操作・縮小表示にも配慮。

### ログ

- 日常（食事・移動）、注目（資金難・再会・大移動）、重大（史実の逸話・死亡・部隊敗走）を区別。
- 各行動に「何をしたか」「なぜ選んだか」「どのデータに基づくか」「介入の影響」を記録。
- 歴史事件の解説画面では、出典と異説、史実とゲーム世界の差を並列表示する。

## 11. 分岐と再現可能性

- 全イベントをバージョン付きで記録し、人物・イベント単位の乱数ストリームを利用。
- セーブに \`RunManifest\` と必要な状態・乱数・世界版・ルール版を含める。
- 介入前状態をスナップショット化して \`baseline\` と \`intervention\` を分ける。元の記録を上書きしない。
- 比較指標：史跡到達率、イベント成立／未成立、人物の生存・離散、物資残量、移動距離、部隊帰属、史実との相違。
- 指標は**ゲーム上の実験結果**であり、現実の歴史の確率ではない。

## 12. MVP「屋島篇」

- 範囲：高松市・屋島・牟礼周辺の限定領域。
- 登場：源平両陣営の8人前後（正式な採用は人物・時期の監査後）。
- 部隊：源氏側、平氏側と分遣隊の抽象モデル。
- 歴史イベント：上記6件程度。確実性と典拠は個別に審査。
- 現代POI：OpenPOIで事前に取得・キャッシュした施設、厳密な分類ができないものは未判定。
- 移動：徒歩・簡易鉄道・固定海路。
- 継続時間：ゲーム内5〜15日程度を調整用の初期目安とする。
- 機能：自動観察、人物追跡、速度変更、イベント説明、助言、介入直前の分岐保存、結果比較。
- 全国展開・実時刻表・フルAI会話・数百人並列運転は初版の範囲外。

## 14. 歴史の正確性と公開境界

- 史実／軍記／伝承／創作の**叙述区分**と、主張の**証拠確認状況**を別々に持つ。
- 「その人物の実在」と「その逸話の実在」を分ける。人名リスト収録だけで実在確定扱いしない。
- 作品の異本による差異は併記し、原典本文を勝手に一本化しない。
- 地点は推定精度・伝承性を明示。史跡所在地から12世紀の厳密な位置を逆算しない。
- AI作成データは \`proposedBy: ai\`, \`reviewStatus: pending\` を基本とし、人による確認前に確定済み教材として提供しない。
- 史料PDFや未許諾の画像・本文、別の非公開リポジトリの内部文書は公開リポジトリへ移さない。
- 悲劇や当時の暴力を無理にゲームの報酬化しない。人物の尊厳と教育的文脈を確保する。

## 15. リスクと対策

| リスク | 対策 |
| --- | --- |
| 施設カテゴリ \`unknown\`、誤座標、閉業残存 | 原情報保存、確度タグ、座標検査、別データで補完 |
| API利用条件・POI再配布 | 出典・ライセンス・取得日をレコード単位保存。公開前監査 |
| 実際にはない交通接続 | POI座標と経路ネットワークを分離 |
| 運命イベントの不発／強制 | 接近・遭遇・成立／未成立を分け、理由も記録 |
| 決定論の破綻 | イベント別乱数、ソート順固定、シード保存 |
| 人物の没年と登場年の矛盾 | 時期フィルターと明示的なIF転移規則 |
| 人物の単純な源平二分法 | 家系と時期依存の所属・同盟を別管理 |
| 計算負荷 | 地域限定・低頻度行動tick・Web Worker |
| 原典の史実誤認 | イベントと人物主張の監査ワークフロー |

## 16. 成功条件（MVP）

1. 登場人物が介入なしでも有限の資源で行動・移動・補給を繰り返す。
2. 史跡の引力が行動候補に影響し、到達不能も合理的に記録される。
3. 同じ初期状態・世界版・乱数シードなら同じログを再生成できる。
4. 一時停止→分岐保存→介入→比較が元のセーブを汚さず成立。
5. 6件程度の屋島イベントに成立・不成立・代替分岐がある。
6. 人物・地点・イベントの典拠／不確実性をアプリからたどれる。
7. 現代施設のゲーム効果を実店舗の事実と誤表示しない。
8. 出典・ライセンス監査が終わるまで問題のあるデータを公開しない。
