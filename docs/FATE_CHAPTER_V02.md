# 屋島篇「運命の刻」v0.2：分岐エンジンと歴史地理の接続口

- 版：0.2／記録日：2026-10-19
- 位置付け：**自由行動を残した架空の章末判定の最小実装。史実再現の戦闘エンジンではない。**
- コード：[fate.mjs](../prototype/fate.mjs)、[core.mjs](../prototype/core.mjs)、[app.mjs](../prototype/app.mjs)、[geography-bridge.mjs](../prototype/geography-bridge.mjs)
- 既存資料：[11人33主張の監査ゲート](YASHIMA_11_RESEARCH_GATE.md)、[屋島8史跡の現代所在地台帳](../data/places/YASHIMA_SITE_REGISTRY.json)

## 1. 設計の中心

「史実に引き寄せられる」ことと「結末が史実どおりに固定される」ことを分ける。

- 人物の自律行動は従来どおり。休息・娯楽・補給・金欠・空腹により行動が遅れる。
- 到着しただけでは即勝利しない。屋島の抽象ノードで、**現在そこに滞在していること**、仮想の時機、体力・食料・士気、助言による交渉意向を見て決断する。
- 世界の時間は独立して経過する。指定刻が過ぎると未到着でも章の結末を確定し、無限待機を防ぐ。
- 章の結果を閉じても人物の生活は続く。次章へのイベント連動は今後の課題。
- プレイヤーの「交渉を勧める」は確率的に受諾されるだけで、人物に交渉を強制できない。

## 2. 状態と分岐

| 状態 | 意味 |
| --- | --- |
| `watching` | 通常の自由行動 |
| `approaching` | 屋島篇の機会が近づく（仮想の第35刻から） |
| `postponed` | 攻勢の準備が足りず、15刻後まで決断を延期 |
| `resolved` | 章の結末が確定。再度同じ章を決着させない |

結果：`upper_hand` 攻勢優位、`stalemate` 膠着、`setback` 攻勢頓挫、`parley` 交渉により即時衝突回避、`retreat` 準備不足で撤退、`empty` 遅い到着で空振り、`missed` 未到着で期限切れ、`withdrawal` 以前に訪問したが決断の機会を失う。

判定はすべて**架空のゲームロジック**。義経以外の平家指揮官・軍勢の実体モデルや戦闘シミュレーションはまだなく、相手勢力の「退避」もゲームシナリオ上の抽象事象。

### 仮パラメータ

- 機会の開始：35刻
- 到着後に決断できる時機：36刻以後
- 対峙できる機会の終盤：82刻
- 章の締切：112刻
- 補給不足なら15刻の延期を一度だけ設定
- 義経の**その場への現在滞在**（`currentStationId === "yashima"`）を満たさない場合、訪問済みでも交戦判定しない

これらはゲーム設計上の調整値であり、1185年の年月日・行軍速度を換算した値ではない。多シード実行の分布を見て調整する予定。

### 分岐の決定因

体力・食料・士気・すでに屋島を訪れた郎党の人数・歴史的引力・交渉助言を使用。乱数を含む戦闘優位の抽象判定は再現可能なシードを使用する。

章の結末は`world.fate.resolution`に固定し、判定理由の配列と実際に発生した義経の施設利用・援助・資金不足などを`journey`として残す。章の後に探索を続けても過去の結果は変わらない。

## 3. 旧日本国名エンジンへの接続余地

歴史地理の共通実装は松尾芭蕉アプリ側が担当し、本アプリはその成果を消費する形にする。

- **ゲーム用抽象位置**：`STATIONS["yashima"]`の画面内の `x,y`。戦場座標や現代緯度経度には**変換しない**。
- **史跡の現在地資料**：`YS001`（`data/places/YASHIMA_SITE_REGISTRY.json`）。広域の代表座標だけ存在。合戦の一点を指定する根拠ではない。
- **歴史地理の意味情報**：`geography-bridge.mjs` の`CHAPTER_GEO_CONTEXT`。時代ラベル1185年頃・讃岐国・史跡ID・利用予定レイヤーを定義。旧国名エンジンの**正式な地物IDはnull**のまま。
- **将来の提供元**：旧国名エンジンから、旧国名の時期付きID、史料、描画ジオメトリ、対応する年代と精度、出典・ライセンスを受ける予定。
- **確認ゲート**：`validateHistoricalGeoResponse` は1185年・典拠・確実性区分・地点IDが揃うことを要求する。通過しても`usableForMovement:false`で、現段階では実ルートを通らせない。

旧国名の境界や道路の線を「平安末期の地図」として予測生成しない。個別の古地図画像・中世海岸線の推定レイヤーは、提供元の出典・作製時期・対象年代を比較してから実装する。

## 4. テスト

- `node --test tests/*.test.mjs`：歴史地理連携契約、訪問と決断の分離、戦闘・交渉・延期・回復・撤退・遅参・失機、同一シード再現、史料台帳整合を検査。
- `tests/headless-smoke.mjs`：PC・スマホ幅のChromeで新たな「交渉助言」「章の結末」「理由と結末保持」を確認。
- GitHub Actions成功をもってコード検証とする。ブラウザ実機Safariの検証は別工程。
- 自動デプロイは既存の`.github/workflows/deploy-pages.yml`に従い、`main`へのコミット後にPagesへ反映。

## 5. 次の作業と停止基準

1. 実際に20〜100シードを走らせ、同じような結末ばかり出ないか、交渉・寄り道・未到着の分岐の頻度を点検する。分布はゲーム試作値であり歴史確率ではない。
2. 決断のタイミングと「章を終えても世界は続く」のUIを実機で監査する。
3. 相手勢力を実体化する前に、個人・部隊・海上移動を混ぜないイベントスキーマを設計する。
4. 旧国名エンジンから受け取れる時代付き地物のサンプルが来たら、地理接続口で型・典拠を検査して結合する。

**今回の打切り**：歴史地名全国整備、旧国境界の復元、平家の軍勢AI、完全な勝敗・死亡シミュレーション、長編の史料再調査は行わない。
